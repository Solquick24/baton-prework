## User Scenarios & Testing *(mandatory)*

### User Story 1 - 바뀐 동행자가 진료 맥락을 이어받기 (Priority: P1)

보호자 B는 이번에 처음 동행하더라도 같은 진료과의 지난 기록에서 바뀐 점과 가족 질문을 확인한다.

**Why this priority**: 진료 인수인계가 바통의 핵심 가치다.

**Independent Test**: 지난 기록과 가족 질문을 준비하고, B가 브리핑에서 변경 사항·질문·근거를 확인한다.

**Acceptance Scenarios**:

1. **Given** 내과의 지난 두 진료와 정형외과 기록이 있음, **When** B가 내과 브리핑을 열음, **Then** 내과 맥락만 표시되고 정형외과 기록은 섞이지 않는다.
2. **Given** 비슷한 가족 질문 두 개가 있음, **When** 질문을 통합함, **Then** 합친 질문에서 원 질문과 작성자를 확인할 수 있다.
3. **Given** 금식 여부에 대한 기록이 없음, **When** 준비사항을 확인함, **Then** 값은 비어 있고 ‘확인 필요’로 표시된다.
4. **Given** 근거가 있는 복약 변경이 있음, **When** 해당 근거를 선택함, **Then** 자기 권한에서 허용된 원문 또는 인용을 확인한다.

### User Story 2 - 공유 범위를 지키며 가족 기록 보기 (Priority: P1)

환자는 가족별 공개 범위를 정하고, 가족은 허용된 정보만 본다.

**Why this priority**: 민감한 진료 내용은 인수인계 편의와 별개로 환자의 통제 아래 있어야 한다.

**Independent Test**: 같은 환자의 기록을 일정만·동행·전체 내용 권한으로 각각 조회하고 허용 정보를 대조한다.

**Acceptance Scenarios**:

1. **Given** 일정만 권한의 가족, **When** 기록을 조회함, **Then** 진료일·예약 일정만 보이고 진료 내용·질문·브리핑은 전달되지 않는다.
2. **Given** 일반 보호자, **When** 자신의 공유 범위를 바꾸거나 다른 가족의 등급을 확인하려 함, **Then** 변경·조회가 거부된다.
3. **Given** 연결되지 않은 사용자, **When** 다른 환자의 기록이나 파일에 접근함, **Then** 내용이 전달되지 않는다.
4. **Given** 가족의 권한이 축소됨, **When** 다음 조회를 수행함, **Then** 축소된 권한이 적용되고 보호 항목의 존재를 알리는 잠금·개수 표시가 없다.

### User Story 3 - 진료 후 기록 정리와 불일치 확인 (Priority: P1)

동행자는 가상 진료 음성과 메모를 정리하고, 가족 메모와 처방의 차이를 확인한 뒤 다음 진료로 이어간다.

**Why this priority**: 다음 보호자가 이어받을 신뢰 가능한 기록을 만든다.

**Independent Test**: 준비한 음성·메모·처방 값으로 진료를 정리하고 결과·불일치·가족 조회를 확인한다.

**Acceptance Scenarios**:

1. **Given** 진료 음성과 메모, **When** 정리를 시작함, **Then** 진행 상태가 보이고 완료 후 주요 설명·복약 변경·다음 일정·질문 답변이 제공된다.
2. **Given** 답변 근거가 없는 질문, **When** 정리 결과를 봄, **Then** 답변을 지어내지 않고 비워 ‘확인 필요’로 표시한다.
3. **Given** 메모와 약봉투의 복용 시간·용량이 다름, **When** 비교 결과를 봄, **Then** 두 근거와 차이가 보이고 어느 쪽이 맞는지 판단하지 않는다.
4. **Given** 검증을 통과한 정리 결과, **When** 저장이 완료됨, **Then** 권한 있는 가족의 다음 조회에 자동 반영되고 미해결 항목은 ‘확인 필요’를 유지한다.
5. **Given** 정리 실패, **When** 상태를 확인함, **Then** 실패를 알리고 재시도할 수 있으며 부분 결과를 완료 기록으로 공유하지 않는다.

### User Story 4 - 읽기 편한 화면과 정적 병원 안내 (Priority: P1)

환자와 보호자는 글씨 크기·고대비를 조절하고 병원 위치·약도를 참고한다.

**Why this priority**: 접근성은 부가 기능이 아니라 핵심 흐름 사용의 전제다.

**Independent Test**: 가장 큰 글씨와 고대비로 핵심 화면을 순회하고 병원 안내를 연다.

**Acceptance Scenarios**:

1. **Given** 가장 큰 글씨·고대비 설정, **When** 다른 화면으로 이동하고 다시 접속함, **Then** 같은 브라우저에서 설정이 유지되고 주요 내용·조작 요소가 잘리지 않는다.
2. **Given** 병원 안내 화면, **When** 위치·약도를 확인함, **Then** 위치와 정적 약도가 보이며 길찾기·경로 계산은 제공되지 않는다.

### User Story 5 - 비공개 메모와 위임·직접 녹음 (Priority: P2)

환자는 비공개 메모를 보관하고 선택한 내용만 의사에게 보여주며, 필요할 때 대표 보호자에게 범위 변경을 위임한다.

**Why this priority**: 1단계 흐름 완주 후 보강하는 환자 통제 기능이다.

**Independent Test**: 환자·대표 보호자·일반 보호자로 메모 접근과 위임 상태별 변경을 확인한다.

**Acceptance Scenarios**:

1. **Given** 비공개 메모, **When** 대표·일반 보호자가 접근함, **Then** 거부되고 가족용 요약·브리핑에도 내용이 섞이지 않는다.
2. **Given** 환자가 메모 일부를 포함 선택함, **When** 의사에게 보여줄 화면을 열음, **Then** 선택한 메모만 포함된다.
3. **Given** 위임이 꺼진 대표 보호자, **When** 공개 범위를 변경함, **Then** 거부되고 위임이 켜져 있을 때만 변경 가능하다.
4. **Given** 직접 녹음 기능, **When** 녹음함, **Then** 환자 허용 설정을 따르고 녹음 중 문구·경과 시간이 계속 보인다.

### Edge Cases

- 기록이 없으면 빈 상태를 보여주고 과거 맥락을 만들어내지 않는다.
- 진료과가 미확인인 기록은 비교·브리핑에 자동 포함하지 않는다.
- 권한 밖 원문은 요약에 연결되어 있어도 전체 문서·음성으로 열 수 없다.
- 같은 작업의 중복 요청은 중복 기록·중복 공유를 만들지 않는다.
- 입력이 수정되면 이전 요약을 최신으로 표시하지 않고 재정리 대상임을 알린다.
- 인식이 불분명한 약 이름·용량·단위는 추정값으로 확정하지 않는다.
- 기다리는 동안 오류가 발생하면 기존 기록을 보존하고 재시도 경로를 제공한다.
- 저장된 대체 결과를 시연할 때 실제 새 처리 결과와 구분해 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 준비된 환자·대표 보호자·일반 보호자 계정으로 로그인하고 허용된 환자 기록을 선택할 수 있어야 한다.
- **FR-002**: 다음 진료·확인 필요 항목·가족 질문·최근 기록을 열람 권한에 따라 제공해야 한다.
- **FR-003**: 가족 질문을 개별 등록하고 작성자·원 질문을 보존한 채 유사 질문을 통합해야 한다.
- **FR-004**: 같은 환자·같은 진료과 기록만으로 브리핑·비교·기록 연결을 수행해야 한다.
- **FR-005**: 브리핑은 바뀐 점·관찰 내용·기록된 준비사항·질문을 제공하고, 전체 타임라인 조회와 진료과별 맥락 구성을 구분해야 한다.
- **FR-006**: 정리된 모든 사실은 근거로 돌아갈 수 있어야 하며, 근거 없는 값은 비우고 확인 필요 여부를 표시해야 한다.
- **FR-007**: 진단·처방 결정·검사 수치의 의학적 해석·치료 권고를 생성해서는 안 된다.
- **FR-008**: 1단계에는 준비한 가상 음성 파일의 텍스트 변환과 메모 입력을 제공하고, 직접 녹음은 2단계로 둬야 한다.
- **FR-009**: 진료 후 주요 설명·복약 변경·다음 일정·질문 답변을 정리해야 한다.
- **FR-010**: 메모·처방의 불일치는 항목별 차이와 두 근거를 제공하고 정답을 자동 선택해서는 안 된다.
- **FR-011**: 불일치에 대해 메모 수정·자료 재등록·병원 확인 예정 중 처리 방식을 남길 수 있어야 한다.
- **FR-012**: 검증된 정리 결과는 저장 후 허용된 가족에게 자동 공유하고, 미해결 불일치는 표시를 유지해야 한다.
- **FR-013**: 실패·검증 실패·처리 중 결과는 완료된 공유 기록으로 노출해서는 안 된다.
- **FR-014**: 기록은 진료과별로 필터링하고, 가족의 현행 공유 범위를 매 조회·변경·원문 접근에 적용해야 한다.
- **FR-015**: 일정만·동행·전체 내용의 열람 범위는 아래 허용표를 따르고, 미정의 정보는 제공해서는 안 된다.
- **FR-016**: 공유 범위 변경은 환자 본인 또는 위임된 대표 보호자만 수행할 수 있어야 한다.
- **FR-017**: 일반 보호자에게 다른 가족의 등급이나 보호 항목의 존재·개수를 전달해서는 안 된다.
- **FR-018**: 비공개 메모는 환자 본인만 접근하고 가족에게 전달되는 처리에 포함해서는 안 된다. 기능 구현은 2단계다.
- **FR-019**: 글씨 크기 3단계와 고대비 설정을 모든 구현 화면에 적용하고 같은 브라우저에서 유지해야 한다.
- **FR-020**: 병원 위치·정적 약도를 제공하고 동선 계산·길찾기·가는 법 안내는 제공해서는 안 된다.
- **FR-021**: 오래 걸리는 처리는 진행·완료·실패를 구분하고 실패 시 재시도할 수 있어야 한다.
- **FR-022**: 가상 데이터·실제 처리·저장된 대체 결과·정적 화면을 시연에서 구분해야 한다.
- **FR-023**: 입력 변경 시 요약의 갱신 필요 여부를 표시하고 수정 전 원본과 수정 내역을 보존해야 한다.
- **FR-024**: 직접 녹음 도입 시 환자의 녹음 허용 설정과 명시적 녹음 중 표시를 적용해야 한다.

### 열람 범위와 단계

| 정보 | 일정만 | 동행 | 전체 내용 |
|---|---|---|---|
| 진료일·예약 일시·병원 위치 | 허용 | 허용 | 허용 |
| 진료과·동행자 | 미허용 | 허용 | 허용 |
| 복약 변경·주의사항·쉬운 요약·바뀐 점 | 미허용 | 허용 | 허용 |
| 가족 질문·권한에 맞는 브리핑 | 미허용 | 허용 | 허용 |
| 위 허용 정보만 담은 근거 인용 | 미허용 | 허용 | 허용 |
| 진단명·검사 수치·전체 문서·전체 녹음·전사 | 미허용 | 미허용 | 허용 |
| 비공개 메모 | 미허용 | 미허용 | 환자 본인만 |
| 다른 가족의 등급·범위 변경 | 미허용 | 미허용 | 환자 본인·위임된 대표 보호자만 |

다른 역할의 ‘전체 내용’ 권한과 범위 관리 권한은 독립적이다.
동행용 근거 인용에는 진단명·검사 수치 등 금지 정보가 섞이지 않아야 하며,
안전하게 분리할 수 없는 인용은 제공하지 않고 확인 필요로 표시한다.

- **1단계**: 로그인·조회·가족 질문·브리핑·음성 파일 변환·메모·정리·비교·공유·타임라인·공개 범위·접근성.
- **정적 안내**: 병원 위치·약도; 방문 경험은 가상 참고 메모로만 제시.
- **2단계**: 직접 녹음·사진 판독·비공개 메모·위임·방문 경험 입력·쉬운 요약 전용 화면.
- **제외**: 회원가입·비밀번호 찾기·실시간 자막·번역·푸시·병원 연동·제3자 매칭·녹음 동의 확인 화면·돋보기.

### Key Entities *(include if feature involves data)*

- **사용자**: 자기 계정으로 접속하는 사람; 환자별로 다른 역할을 가질 수 있다.
- **환자·구성원 관계**: 기록 주인, 연결된 사용자, 역할, 공유 범위, 위임 상태.
- **진료 기록**: 진료과·병원·일정·동행자·원본·정리·공유 상태·수정 이력.
- **가족 질문**: 질문 내용·작성자·원 질문·통합 결과·추가 질문의 근거.
- **근거**: 원본 식별자·위치·인용과 해당 근거를 열람할 수 있는 범위.
- **확인 항목**: 부족한 근거 또는 불일치·참조 원본·처리 상태·수정 이력.
- **처리 작업**: 요청 대상·입력 버전·진행 상태·결과·실패 이유.
- **비공개 메모**: 환자 본인의 메모·의사에게 보여줄 포함 선택.
- **화면 설정**: 글씨 크기·고대비.

## Success Criteria *(mandatory)*

### Measurable Outcomes

아래 수치는 출시 성능 보장이 아니라 MVP 수용 검증의 목표다.

- **SC-001**: 시드 시나리오에서 B가 브리핑을 30초 동안 읽고 준비된 복약 변경과 질문 3개를 모두 찾을 수 있다.
- **SC-002**: 검증용 정리 항목 100%에 열람 가능한 근거 또는 빈 값과 확인 필요 표시가 있다.
- **SC-003**: 정의된 역할별 검증 시나리오에서 금지 정보의 전달·열람은 0건이다.
